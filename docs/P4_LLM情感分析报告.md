## 一、任务设计

| 环节 | 方案 | 为什么这么做 |
|------|------|-------------|
| 数据 | 去重后的葡语文本评论（每单最新一条） | 复用 P1 质检口径（坑2） |
| 抽样 | 分层抽样 1~5 星每档 200，共 1,000 | 每档都有样本，才能算"分档一致率"；1000 条统计上足够，成本可控 |
| 调用 | 20 条/批 + JSON 结构化输出 | 批量省 95% 请求数；结构化输出免解析翻车 |
| 验证 | LLM 情感 vs 用户真实打分交叉对比 | **核心**：证明"用了 AI"不如证明"知道 AI 哪里可信" |

## 二、核心结果 1：幻觉验证——LLM 的能力边界地图

总体一致率 **70.9%**（n=1000），但真正的发现藏在分档里：

| 用户评分 | 一致率 | 解读 |
|---------|--------|------|
| 1 星 | **97.0%** | 极端负面：LLM 几乎全对 ✅ |
| 2 星 | 84.5% | 较准 ✅ |
| 3 星 | **12.0%** | ⚠️ **中性是 LLM 的盲区** |
| 4 星 | 67.5% | 偏好文字带抱怨，易被高估负面 |
| 5 星 | 93.5% | 极端正面：几乎全对 ✅ |

**结论模式：极端可靠，中间模糊。** 这不是失败，是价值最高的发现——

> **工程启示**：LLM 情感分析不能盲信，但可以"路由"——1/2/5 星全自动处理（可信度 >84%），3/4 星转人工复核（LLM 最重要的价值判断）。这套"置信度路由"思路是 AI 落地的通用范式，Step 2 的 Agent 同样适用。

**3 星为何崩到 12%？** 两个原因：①打 3 星的用户文字往往带明显情绪（偏正或偏负），LLM 读文本没错，是"3 星=中性"这个映射本身模糊；②中评的语义空间天然连续，硬三分类必然失真。**这告诉我们：错不在模型，在任务设计——把连续情感硬切三段。**

## 三、核心结果 2：负面归因——与 P3 证据链闭环

LLM 判负面的 553 条评论归因分布：

| 主因 | 条数 | 占比 |
|------|------|------|
| **物流延误（logistics_delay）** | 198 | **35.8%** |
| 商品质量（product_quality） | 195 | 35.3% |
| 卖家/发货服务（seller_issue） | 138 | 25.0% |
| 其他 | 22 | 4.0% |

**证据链至此完整闭环**：
1. P2 模块 08：1 星订单迟到率 37.9%（量化相关）
2. P3 模块 11：2018 迟到率上行 6.5%→9.3%（风险预警）
3. **P4：LLM 读懂了葡语文本，独立得出"物流是差评第一大主因（35.8%）"**

三种独立方法（统计相关 / 时间趋势 / 文本语义）指向同一结论——这就是**三角验证**，报告可信度的天花板。

## 四、业务建议补充（P3 建议的量化修订）

P3 建议一"提升复购/改善物流"现在有了优先级依据：
- **物流改进 ROI 最高**：35.8% 的差评源于物流，且 08 模块证明它与低分强相关——修物流 = 同时打两个痛点
- 商品质量 35.3% 位居第二 → 卖家准入/质检机制是第二优先级
- seller_issue 25% → 发货时效 SLA 可以写进卖家协议
